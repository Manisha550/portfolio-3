# Retrospective — AI Fluency Track

**To the version of me who started this in Week 1,**

You went into this thinking you'd end up with "a portfolio website." You did — but that undersells what actually happened along the way, so let me catch you up.

## What I set out to do

The goal in Week 1 was simple on paper: build a clean, responsive portfolio site to showcase my UX/UI design work — case studies, project screenshots, an about section, a way for people to reach me — and use it as proof of what I can actually do, not just a list of claims on a résumé. I picked HTML, CSS, and vanilla JavaScript on purpose, no framework, because I wanted to actually understand what was happening in the code I was shipping, not just wire up a template. Figma for the design work, GitHub for version control, Vercel for deployment. That was the whole plan.

## What changed

The site itself changed a lot between the first draft and now — visual hierarchy, typography, spacing, and navigation all went through several passes before they felt right, and real project screenshots eventually replaced what were originally just decorative placeholders. But the bigger shift wasn't in the code — it was in how I worked.

Early on, I treated AI as something you asked for a finished answer. By the end, I was using it more like a collaborator I still had to manage: brainstorming layout options, refining copy, catching things I'd have missed in a proofread, helping me think through documentation — while every actual design decision, every piece of customization, and every line of final implementation stayed mine to make and test. That's a meaningfully different relationship than where I started. I stopped asking "can AI do this for me" and started asking "where does AI actually save me time without taking the judgment calls away from me."

I also learned to be honest about limitations instead of hiding them. My contact form still has limited backend functionality. Dark mode isn't built yet. I have more case studies to add. Week 1 me would have wanted to hide all of that until it was "finished." Now I know a shipped, honest, imperfect thing beats a hidden, theoretical, perfect one — and that naming the gaps openly reads as credibility, not weakness.

## What I'd build next

A few concrete things: proper backend handling for the contact form instead of a placeholder, two to three more detailed UX case studies with real process documentation (not just final screens), basic filtering on the projects page, analytics so I actually know if anyone's visiting, and eventually moving the site to a custom domain instead of the default Vercel subdomain. None of these are hard — they just weren't the priority for a first working version, and now that the foundation is solid, they're the natural next layer.

## The three most transferable things I learned

**First:** documentation is not an afterthought — it's part of the deliverable. A stranger should be able to clone my repo and get it running from the README alone, and writing that README forced me to actually understand my own project structure better than I did before I wrote it.

**Second:** transparency about AI use isn't a confession, it's a credibility signal. Naming exactly what AI helped with and what I did myself is more convincing than pretending the whole thing sprang fully formed from just me — and it's also just true.

**Third:** testing is a discipline, not a formality. Going through navigation, responsiveness, links, and visual consistency systematically — instead of just "it looks fine to me" — caught real issues before anyone else saw them. That habit will outlast this specific project.

I set out to build a portfolio. I ended up learning how to actually finish something, document it honestly, and be straight about where the help came from. That's the part I'm keeping.

— Sumaiya
