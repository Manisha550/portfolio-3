04 — Redesign · Web app · Education

Redesigning my own university's student portal, one dashboard at a time.

IIUC's student portal spreads CGPA, attendance, courses, and payments across separate pages with dated UI. I redesigned it as a single dashboard — using my own student account's real data as the content.

RoleUI/UX Designer (solo)
PlatformWeb — desktop-first
ToolsFigma
Timelineadd duration
This is a self-directed redesign of an existing university system, used as a case study, and isn't an official IIUC deliverable. Grades, CGPA, and course data shown are pulled from a real portal session for authenticity — replace with anonymized data if this is shared publicly.
Overview

Every important number, one screen

The redesign keeps the university's original green-and-white brand identity but restructures the content: a profile card, current CGPA, attendance ring, a course list with grades and status, a calendar, and quick links (Library, Payment, Course Status, Syllabus, Question Bank) all live on one dashboard instead of a multi-page click-through.

Problem

The information exists. Finding it is the problem.

The original portal isn't missing data — CGPA, attendance, and course status are all there. The problem is retrieval cost: a student checking their standing before registration has to open several separate pages to piece together one picture. The redesign's entire premise is that this is an information-architecture problem, not a content problem.

Users
  • Students checking in routinely — attendance percentage before it drops below the eligibility threshold, CGPA before an advising meeting.
  • Students at decision points — before course registration, before a semester deadline — who need several data points at once, not one at a time.
Research

Auditing the existing portal as the primary research method

As an actual IIUC student, I used my own portal use as the research base: which pages I opened most often, which numbers I checked right before a deadline, and where I habitually got stuck. That first-hand audit is why attendance and CGPA — the two numbers I checked most under time pressure — got dedicated ring-chart treatment at the top of the dashboard instead of being buried in a table.

Competitive analysis

Pattern seen

The original portal uses a traditional sidebar-and-table layout with little visual hierarchy between a routine number and an urgent one.

Design response

CGPA and attendance became circular progress indicators with colour-coded status, borrowed from consumer dashboard conventions students already recognise from other apps.

Persona
S

Sumaiya, final-year CSE student, semester 7 of 8

Goal: confirm CGPA and attendance are on track before advising week.
Frustration: the current portal requires four separate page loads to answer one question: "am I okay this semester?"
What she needs: that answer on the first screen she sees after logging in.

Information architecture

Left-hand sidebar groups by function — Academic (Schedule, Homeworks, Exam Routine, Course Status, Grade Report, Attendance, Enrolled Courses, Select Supervisor), Administrative (Remaining Balance, Announcements), and Settings — while the main panel surfaces the small set of numbers that answer "how am I doing right now" without needing the sidebar at all.

User flow

Login → dashboard loads with profile, CGPA, and attendance immediately visible above the fold → student scans the course list for any outstanding grade or assignment flagged in red → uses quick links only for a specific task (paying a bill, checking the syllabus). The redesign's success condition is that most check-ins never require leaving this one screen.

Wireframes

Grid-first, content second

I blocked out the dashboard as a three-column grid — profile/quick-links, CGPA/attendance rings, calendar/assignments — before placing any real content, to make sure the layout would hold up regardless of how many courses or announcements a given student has.

Design process & UI decisions

Keeping the institution's identity, replacing the interaction model

I deliberately preserved IIUC's green brand colour and university header rather than replacing it with a generic redesign palette — the point was to demonstrate an improvement the university could plausibly adopt, not to reskin it as a different product. Status colours (green for "Completed," red for "Pending") follow the same logic as the original portal so returning students wouldn't need to relearn the system.

Challenges

Fitting a calendar, a course table, and two ring charts on one screen without it turning into visual noise was the main constraint — university dashboards easily become "everything, everywhere." I addressed it by giving the course table the most horizontal space (it has the most rows to scan) and compressing the calendar to a compact month view rather than a full scheduling grid.

Reflection

Redesigning a system I use myself, weekly, made the usual "empathize with the user" step almost too easy — the harder discipline was noticing my own workarounds and not just designing around them, but questioning why they were necessary in the first place.

Next improvements
  • Design the mobile version — the current mockup is desktop/laptop only.
  • Add a notification system for grade releases and attendance drops below threshold.
  • Share the redesign with a handful of classmates for real feedback before treating any of the above as validated.
